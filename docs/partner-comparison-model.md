# Plan 09 — Partner Comparison State Model

## Principle

Partner comparison is optional and descriptive. It does **not** compute an overall compatibility percentage. A single number would hide direction, fantasy/reality differences, conditions, boundaries, and missing data.

The app loads a second response export into memory on the Results screen. The partner response is not written into the app's local persistence state.

## States

### Strong directional match

Complementary perspectives are both strongly positive, for example one person's Giving response paired with the other person's Receiving response, or dominant paired with submissive.

### Shared mutual interest

The same non-directional/mutual perspective is strongly positive for both people.

### Possible discussion

Both sides contain enough data to compare but the pattern is not a strong match, hard-limit conflict, fantasy/reality mismatch, or explicit conditional match. This is deliberately neutral wording and is not a recommendation to persuade anyone.

### Fantasy / real-world mismatch

One response is fantasy-only (or fantasy-positive but real-world negative) while the paired response indicates real-world desire. The state preserves the distinction instead of treating fantasy appeal as consent to enactment.

### Conditional match

At least one paired response is conditional and there is no hard-limit conflict. Conditions must be discussed directly; the state is not treated as unconditional compatibility.

### Hard-limit conflict

A concept, subtype/detail, or category-wide hard limit conflicts with the other response's positive interest. This state takes precedence over positive match states and is shown first. Hard limits are not averaged, discounted, or framed as something to negotiate away.

### Insufficient data

One side lacks enough answer data for that paired interaction. It is not treated as disinterest or incompatibility.

## Direction mapping

The initial model pairs these complementary perspectives:

- giving ↔ receiving
- dominant ↔ submissive
- owner ↔ owned
- observing ↔ being observed
- feeling an emotional state ↔ seeing/evoking it in a partner

Other perspectives compare to the same perspective when applicable.

## Boundary precedence

1. Category hard-limit conflict.
2. Concept hard limit.
3. Matching adaptive-detail/subtype hard limit.
4. Fantasy/real-world mismatch.
5. Conditional match.
6. Positive match/discussion states.
7. Insufficient data where a pair cannot be evaluated.

The model intentionally has no total score, weighted average, or "percent compatible" output.
